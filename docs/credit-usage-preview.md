# Credit 套餐与统计预览

## 本地查看

在 `webapp` 运行现有开发服务后：

- `/?open=relay`：套餐与权益，升级入口采用新版 V1/V2/V3 卡片。
- `/credit-usage-preview.html`：独立桌面统计原型；支持用户、Agent、模型、时间筛选，趋势/来源图表、调用详情和 CSV 导出。
- 左侧“额度规则”提供消费、邀请赠送、充值及月额度抵欠款的交互试算。

统计页面仅为开发预览入口，没有加入生产构建或管理员路由；它不调用真实 API。用户、Agent、回执和价格均是演示数据。全部汇总、图表和 CSV 共用 `webapp/src/demos/credit-usage/data.mjs`，共有 45 条已结算调用和 1 条待结算调用，已结算总额 44.080395 credit。待结算不计入已消费汇总；新增欠款是期间增量，不等于账户当前欠款。

## 套餐与计算边界

新个人套餐用独立商品 slug，不将旧 Token 订单或余额重新解释为 credit。未匹配后端商品时禁止创建订单。已有订单和账户路径保留原产品语义；本次没有迁移后端余额、发放配额、模型权限或收费规则。

规则依据见 [已确认规则](credit-plan-rules-20261109.md)。试算覆盖月额度 → 邀请赠送 → 付费充值 → 欠款，赠送不抵欠款，充值与下期月额度先抵欠款。扣款后能否启动/恢复任务，还取决于模型权限和调度器验证。

演示计算采用整数微 credit、每次调用四舍五入至 6 位小数；原始购买日作为月末后续期锚点是实现建议。精度、汇率和价格版本管理需与后端统一，不能把试算当作线上结算接口。调度器应原子化选择最近开始执行的一个根任务继续，保存其他任务进度；页面中的选择示例不执行真实任务暂停或恢复。

## 数据接入顺序

1. **统一分账账本与调度校验。** 月额度、邀请赠送、充值余额、欠款分别留账；消费、周期发放、充值、赠送、抵欠和未来退款采用独立事件及幂等键。自然月与升级补差需由后端执行，不能仅修改商品价格后开放新套餐。
2. **保留逐次调用证据。** 记录 actor/payer UID、Agent、根任务及父任务 ID、请求与网关回执 ID、非缓存输入/缓存输入/输出 Token、价格/费率/汇率快照、发生/结算时间、账本顺序、扣款来源和余额前后。流式增量、重试、晚到回执与冲正不得重复扣费。
3. **提供管理端查询与聚合。** 服务端校验管理员权限，提供分页与筛选；汇总、明细和导出使用同一统计快照。明确区分 pending、settled、failed、reversal。普通用户不能通过修改 UID 查询其他用户。
4. **独立对账。** 用量回执 → 价格与权益快照 → 分账账本 → 统计。不通过消费流水推算全部当前余额；服务/第三方应用收费与模型调用分开。

已有的 `server/service_run_ledger_writer.go`、`server/relay_credit_settlement.go` 提供服务调用的幂等账本/代扣机制；它们不能直接等同于新的三来源模型调用账本。退款政策及环境保留是否包含持续计算仍待确定。

## 验证

运行 `webapp` 现有 Vitest 检查 `src/demos/credit-usage/billing.test.js`、套餐弹窗、会话状态提示及消息视图测试。浏览器检查应覆盖筛选后的汇总与 CSV 对账、时间排序、待结算、空结果、详情滚动和主题切换。
