# CatsCo 流式 STT 成本与容量核对（2026-08）

访问日期：2026-08-10（Asia/Singapore）

本文只把厂商官方公开页面能直接确认的内容列为“事实”。小时成本、带宽和月账单场景均为基于公开单价或音频规格的工程估算，不代表厂商报价；实际价格、优惠、税费、地域和账号控制台配置应在上线前再次核对。

## 结论

> CatsCo 的实现选择已经确定为火山引擎 **豆包流式语音识别模型 2.0**。
> 当前代码使用新版控制台 API Key、优化双向流式 WebSocket，以及 2.0
> 小时版资源 ID `volc.seedasr.sauc.duration`。路径中的 `bigmodel_async`
> 是官方协议端点名称，不代表回退到 1.0 商品。

- 如果 CatsCo 采用阿里云北京地域 `fun-asr-realtime`，公开原价为 **0.00033 元/秒，即 1.188 元/音频小时**。新人额度为每个模型 36,000 秒（10 小时），仅北京地域，90 天有效。
- `voicepi` 当前火山引擎配置默认连接 `/api/v3/sauc/bigmodel`，资源 ID 为 `bigmodel`，对应应按 **大模型流式语音识别** 预算。公开后付费价格为 **4.5 元/音频小时**，正式版默认 10 并发。
- 火山引擎另有 **豆包流式语音识别模型 2.0**，后付费为 **1 元/音频小时**，正式版默认 50 并发。它是不同商品/资源，不应在未验证 CatsCo 协议和资源 ID 的情况下，把这个低价直接套到 `voicepi` 的 `bigmodel` 接入上。
- STT 推理费远高于 CatsCo 中转 PCM 的常规网络费。真正容易先碰到的容量约束是“每个长连接占一个上游并发”和代理进程的文件描述符、内存、心跳与超时管理，而不是 CPU 编解码；前提是后端不做重采样或复杂 DSP。

## 1. 阿里云 DashScope `fun-asr-realtime`

### 官方事实

| 项目 | 北京地域 | 新加坡/国际 |
|---|---:|---:|
| 原价 | 0.00033 元/秒 | 0.00066 元/秒 |
| 折算每小时 | 1.188 元/小时 | 2.376 元/小时 |
| 新人免费额度 | 36,000 秒（10 小时） | 无公开免费额度 |
| 免费额度有效期 | 90 天 | 不适用 |
| 模型页公开限流 | 1,200 RPM | 1,200 RPM |

计费规则是按输入音频秒数计费，输出不计费。北京地域免费额度只适用于首次开通后符合条件的模型；主账号和 RAM 子账号共享额度，不同模型及快照版本的额度相互独立。免费额度到期或耗尽后会进入按量计费（除非账号开启“免费额度用完即停”）。

`1,200 RPM` 是每分钟请求数限制，不等同于可同时保持 1,200 条长连接。公开模型页未给出一个可以直接当作 CatsCo“最大同时在线录音人数”的并发数字，因此阿里云并发容量在采购/压测前仍需通过控制台配额或工单确认。

官方 WebSocket 文档确认客户端通过全双工 WebSocket 发送二进制单声道音频，同时接收 `result-generated`，最后发送 `finish-task` 并等待 `task-finished`。接口支持 PCM、WAV、MP3、Ogg Opus、Speex、AAC、AMR 等格式；8 kHz 模型仅支持 8,000 Hz，其他模型公开为支持任意采样率。官方示例采用 PCM16、16 kHz、单声道，并以 3,200 字节约每 100 ms 发送一帧。

| 月音频时长 | 估算推理费 |
|---:|---:|
| 100 小时 | 118.80 元 |
| 1,000 小时 | 1,188 元 |
| 10,000 小时 | 11,880 元 |
| 100,000 小时 | 118,800 元 |

一次 30 秒语音约 `0.0099 元`，一次 60 秒语音约 `0.0198 元`。厂商按音频时长收费，流式传输本身不会因为拆成更多 WebSocket 帧而增加音频时长费用；异常重连后重复发送同一段音频可能造成重复计费，应避免无界重放。

## 2. 火山引擎实时语音识别

### 与 `voicepi` 的接入差异

- WebSocket 路径：`/api/v3/sauc/bigmodel`
- 资源 ID / 模型名：`bigmodel`

CatsCo 使用同一 v3 二进制协议族的优化双向流式端点
`/api/v3/sauc/bigmodel_async`，但通过资源 ID
`volc.seedasr.sauc.duration` 明确选择 **豆包流式语音识别模型 2.0** 小时版。
新版控制台只需要 `X-Api-Key`；上线前仍需在 `test` 环境用实际 API Key
完成一次端到端识别验收。

## 3. 带宽与代理资源估算

### 未压缩 PCM16

假设 CatsCo 采用 `16,000 Hz × 16 bit × 单声道`：

```text
16,000 samples/s × 2 bytes/sample = 32,000 bytes/s
= 256 kbit/s
= 115.2 MB/音频小时（单方向，十进制）
```

若浏览器把 PCM 发给 CatsCo，CatsCo 再原样转发给上游，每条活跃流大约产生：

- CatsCo 入站：32 KB/s
- CatsCo 出站：32 KB/s
- 合计经过 CatsCo 网卡的数据量：约 230.4 MB/音频小时
- 对通常只计公网出站流量的云主机账单，关键值约为 115.2 MB/音频小时；具体是否免费内网、是否跨地域收费取决于部署商，本文未代入单价。

并发 100 路持续 PCM 时，单向吞吐约 `25.6 Mbit/s`，双向合计约 `51.2 Mbit/s`，尚未计 WebSocket/TLS 包头、重传和控制消息。并发 1,000 路时对应约 `256 Mbit/s` 单向，网络和连接管理会开始成为显著容量项。

### Ogg Opus

阿里云公开支持 Ogg 封装的 Opus，火山引擎产品页也公开支持 Opus。若实测后选用约 24 kbit/s 的 Opus（**24 kbit/s 是工程假设，不是厂商要求**），单方向约为 10.8 MB/小时，相对 PCM16 约减少 90.6% 的音频载荷。

但浏览器 `MediaRecorder` 产生的具体容器、分片边界和 MIME 支持存在浏览器差异。不要仅为省带宽在 CatsCo 后端做同步解码和重编码；这会引入 CPU、排队延迟和更多故障模式。优先顺序应为：

1. 先用 PCM16 端到端打通并测量真实并发、首字延迟和账单。
2. 上游协议直接接受浏览器可稳定产出的 Ogg Opus 时，再做透传优化。
3. 只有网络成本或容量数据证明必要时，才增加服务端转码层。

## 4. 容量与采购建议

### 早期阶段

- 默认按 **阿里云 1.188 元/小时** 或 **火山大模型 4.5 元/小时** 的无折扣价格做预算，避免把一次性免费额度写进长期单位经济模型。
- 为每个会话设置录音上限、空闲 VAD 超时和硬超时；静音仍可能持续占用并发或被计入发送的音频时长。
- 记录供应商、模型、会话音频毫秒数、重试音频毫秒数、连接持续时间和最终账单 usage，才能校准“客户端录音时长”和“厂商计费时长”的差异。

### 何时考虑资源包或纯并发

- 资源包是否划算取决于一年内可确定消费的小时数，而不是峰值并发。
- 火山“大模型流式”纯并发版与后付费的理论盈亏点约为每个已购并发每月 `1,500 / 4.5 = 333.3 小时`，即该并发槽月利用率约 46.3%（按 30 天计）。低于此利用率通常按小时更便宜。
- 火山“豆包流式 2.0”纯并发版理论盈亏点为 `500 / 1 = 500 小时/月`，约 69.4% 月利用率。上述只是公开原价的数学比较，未计资源包折扣、商务优惠与并发峰谷。

## 5. 尚未确认、上线前必须复核

- 阿里云 `1,200 RPM` 下的实际 WebSocket 同时连接上限、单会话最长时长，以及是否能按 workspace 单独申请扩容。
- 火山引擎控制台对目标 API Key/Resource ID 实际发放的免费试用小时和并发。
- `voicepi` 的 `/api/v3/sauc/bigmodel` 是否在目标火山账号中被映射到文档里的“大模型流式语音识别”同一计费商品；应以开通页和首笔账单验证。
- CatsCo 部署地域到阿里云北京/新加坡或火山语音服务的公网 RTT、丢包、TLS 握手时间和跨云出站单价。
- 供应商对静音、尾部等待、失败会话、客户端取消与重连重放的实际计费边界。

保守预算建议：先把供应商推理费作为主成本，以后付费运行一段有监控的真实流量；只有账单和并发利用率数据稳定后再购买资源包或纯并发版。
