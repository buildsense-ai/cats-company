# Public model access and Free Terra trial

Migration 000020 limits public `catsco-personal` (Pro) and `catsco-pro` (Max) to
MiniMax-M2.7, MiniMax-M3, deepseek-v4-flash, glm-5.3-flash and gpt-5.6-terra.
Their total platform allowances remain 10500 and 31500. Sol is retained for
internal/custom grants; Luna is disabled in the current application/Relay.

Open order snapshots are updated. Fulfilled history and manual/internal grants
are preserved. Existing public package grants, including future renewals, are
replaced with audited five-model grants at the same total and effective interval.
The startup migration uses the same SQL and can run repeatedly. The down migration
restores seven-model public allocations without erasing usage or trial spend.

Deploy the corresponding Relay support before this application. The syncer uses
`limits.free_terra_trial` as a capability marker and sends an explicit boolean
policy in the same limits request as scopes/shared budgets. No recurring Terra
grant is inserted for Free: its synthetic 100-unit model entry is used only in
reconciliation and user model lists. The existing Free pool stays unchanged.

Any current paid/internal entitlement, or a current positive operator Terra
grant, disables trial mode. The Relay retains lifetime spend, so upgrades restore
normal paid/internal access while later downgrades cannot regenerate the trial.
Requests admitted before the switch finish under their original wallet.

The migration changes model access, not prices, duration, cloud-worker credits,
payment signatures or historical usage. A user with an existing Sol/Luna bot on a
public package needs to select an allowed model. Cloud model selection reaches
XiaoBa through its existing runtime catalog; this change needs no XiaoBa package.

Rollback must coordinate with Relay: do not run old Relay code against active
trial scopes. Keep Relay trial tables across application and schema rollbacks.
