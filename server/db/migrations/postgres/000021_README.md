# Public image model access

Migration 000021 adds the image lane models (gpt-image-2, gpt-image-2.5,
gpt-image-2.5-flare, gpt-image-2.5-sunburst, chatgpt-image-latest) to
`catsco-personal` (Pro) and `catsco-pro` (Max) on top of the five public chat
models. The advertised pool grows by the add-on: 10500 -> 11000 and
31500 -> 33000. Image calls draw from the same shared pool as the chat models.

Open order snapshots are updated. Existing public packages, including future
renewals, receive the image grants at their original interval; the five chat
grants stay untouched. Only packages that currently hold exactly the public
five-model set qualify, so internal/custom plans, manual grants and fulfilled
history are preserved. The add-on amount follows the plan (Personal 100, Pro
300 per image model) and is independent of the original package total. The file
runs under a transaction-scoped advisory lock so two concurrent startup runs
cannot double the add-on; it remains repeatable on its own.

## Rollback order

Run `000021_commercial_image_models.down.sql` BEFORE
`000020_commercial_public_models.down.sql`: the 000020 rollback expects
five-model packages without image grants. Rolling back the application without
reverting this migration will re-apply the add-on on the next boot, so the
migration must be removed together with the code rollback.

## Relay prerequisite

The relay loads its model catalog dynamically, so no relay package change is
required here. The upstream account/provider (`pptoken-image-search`) must
already expose the five model names, because purchase validation
(`validateCommercialRelayModels`, `server/commercial_relay_sync.go`) matches
plan budgets against the live catalog exactly and would reject purchases while
the mapping is missing. Production was verified to expose all five names.
